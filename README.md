# Diabetes Prediction API

A basic FastAPI application that serves predictions from a trained Random Forest classifier on the [Pima Indians Diabetes dataset](https://www.kaggle.com/datasets/uciml/pima-indians-diabetes-database/). Built as part of an API lab covering endpoint creation, model serving, and error handling.

## Project Structure

```
Diabetes_API_Lab/
└── app/
    ├── main.py            # FastAPI application (serves UI + /predict endpoint)
    ├── train_model.py     # Trains RandomForestClassifier, saves model.pkl
    ├── model.pkl           # Trained model (generated by train_model.py)
    ├── diabetes.csv        # Dataset
    └── templates/
        └── index.html      # Simple form UI for testing predictions
```

## Setup

```bash
pip install fastapi "uvicorn[standard]" scikit-learn joblib jinja2 pandas python-multipart
```

1. Place `diabetes.csv` in the `app/` folder.
2. Train the model:
   ```bash
   cd app
   python train_model.py
   ```
   This generates `model.pkl` in the same folder.
3. Run the API:
   ```bash
   python -m uvicorn main:app --reload
   ```
4. Open `http://127.0.0.1:8000/` in a browser (do **not** open `index.html` directly as a `file://` path — it must be served by uvicorn or the `/predict` fetch call will fail).

## Endpoints

| Method | Path       | Description                                  |
|--------|-----------|-----------------------------------------------|
| GET    | `/`        | Renders the prediction form (`index.html`)    |
| POST   | `/predict` | Accepts form data, returns prediction + probability |
| GET    | `/docs`    | Auto-generated Swagger UI (FastAPI/OpenAPI)   |

### `/predict` request fields
`pregnancies`, `glucose`, `bloodPressure`, `skinThickness`, `insulin`, `bmi`, `diabetesPedigreeFunction`, `age` — all required floats, sent as form data.

## Known Issues / Debugging Log

This project hit several environment and path-related issues during setup, documented here for reference:

- **`uvicorn` not recognized as a command** — `uvicorn.exe` wasn't on PATH. Fixed by invoking it as a module instead: `python -m uvicorn main:app --reload`.
- **`Could not import module "main"`** — uvicorn was run from the parent `Diabetes_API_Lab` folder instead of `Diabetes_API_Lab/app`, so it couldn't find `main.py`. Fixed by always running uvicorn from inside `app/`.
- **`FileNotFoundError: model.pkl` / `diabetes.csv`** — both `main.py` and `train_model.py` load these files using relative paths, which only resolve correctly if the terminal's working directory is `app/` when the process starts. Fixed by rewriting `main.py` to resolve paths relative to the script's own location:
  ```python
  BASE_DIR = os.path.dirname(os.path.abspath(__file__))
  model = load(os.path.join(BASE_DIR, "model.pkl"))
  templates = Jinja2Templates(directory=os.path.join(BASE_DIR, "templates"))
  ```
  This makes the app robust to being launched from any working directory.
- **"Internal Server Error" with no visible detail** — Starlette's default 500 handler hides tracebacks from the browser. The actual exception is only visible in the terminal running uvicorn, not the browser — always check the server terminal, not just the browser page, when debugging.
- **Predict button not updating the page** — caused by opening `index.html` directly from disk (`file:///...`) instead of via the running server (`http://127.0.0.1:8000/`). The form's JavaScript `fetch('/predict', ...)` call requires a real HTTP origin to resolve correctly.

## Next Steps (Error Handling Enhancement)

Per the lab task, the following hardening is planned/in progress:
- **Input validation** — reject out-of-range values (e.g. negative age, glucose > 300) with a `422` and descriptive error, beyond FastAPI's default type checking.
- **Rate limiting** — using `slowapi` to return `429 Too Many Requests` if the endpoint is hit too frequently, simulating basic load protection.
- **Safe inference** — wrapping `model.predict()` in a try/except so a malformed input or model error returns a clean `500` with a JSON message instead of an unhandled crash.
